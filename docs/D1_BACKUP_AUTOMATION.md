# OtyaPoint backup and recovery policy

OtyaPoint business data and recovery copies are private. This public document describes the policy only; it does not publish storage names, backup object paths, account identifiers, API token names, hashes or operational commands.

## Backup principles

- Business backups are encrypted or protected by the storage provider's private access controls.
- Backups are generated by an approved automated process using least-privilege access.
- Exported data is handled as confidential business information.
- Temporary runner files are removed after verification.
- Logs contain status and safe metadata only; never credentials, customer data, signed download URLs or raw business records.

## Verification

A successful upload is not sufficient. The automation must read the object back and verify byte count and a cryptographic checksum. Recovery copies must be restored into an isolated environment and checked for schema, migration history and business-record consistency.

## Recovery readiness

The schedule, retention period, alert routing and recurring restore-drill evidence must be reviewed by the Otya operations owner. Do not label backups fully operational until scheduled runs and restore tests have succeeded.

## Access control

Backup credentials must be scoped to the minimum required account and operations. They must never be committed to this repository, included in public documentation, pasted into chat or written to logs. Detailed access policy and recovery instructions belong in a private Otya operations workspace.
